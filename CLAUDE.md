You are Claude Code working inside the **sxt-tools** repository: a Claude Code marketplace shipping three plugins (`dreamspace-data`, `dreamspace-query`, `dreamspace-contracts`) and five skills that take a CSV from a local folder to a verifiable Proof-of-SQL event on Base mainnet via Space and Time chain.

## Architecture in one paragraph

A user's CSV is published to SXT chain via two Substrate extrinsics (`tables.createNamespace` + `tables.createTables` then `indexing.submitData`). The chain indexer promotes the table into the dreamspace.xyz Studio MAINNET catalog. A user-deployed Solidity contract on Base calls `IQueryRouter.requestQuery` with a hex-encoded proof plan generated by the SXT chain RPC `commitments_v1_evmProofPlan`. The SXT executor reads the plan, runs the SQL against the indexed table, generates a HyperKZG proof, validates it through Base's onchain Verifier in ~150K gas, and calls back into the user's contract — emitting an event that's a trustless cryptographic receipt. The five skills wrap each step.

## Load-bearing rules (NEVER break these)

### Publishing
- **NEVER emit `PRIMARY KEY` in CREATE TABLE.** SXT chain accepts the DDL and rows ingest, but the dreamspace MAINNET indexer silently skips promotion → off-chain `/v1/zkquery` returns `422 "does not exist in source network MAINNET"` → on-chain executor silently drops `query()` calls → 100 SXT locks until 1-hour timeout. Verified failure mode that cost us 200 SXT before discovering it. `publish-dataset-cli.mjs:117` is the load-bearing line — keep it `NOT NULL`-only.
- **Default `SXT_RPC` is `wss://rpc.mainnet.sxt.network`** (mirrors canonical [`spaceandtimefdn/sxt-chain-examples`](https://github.com/spaceandtimefdn/sxt-chain-examples/tree/main/tutorials/create_hello_world_table)). Testnet is opt-in via env override.
- **Namespace must end with the publishing wallet's uppercase hex address.** `publish-dataset-cli.mjs` auto-suffixes — don't bypass.
- **Apache Arrow vectors must carry explicit types** (`vectorFromArray(values, new Utf8())`). Inferred typing via `tableFromJSON` is rejected with `indexing.ArrowExpectedRecordBatchMessage`.

### Off-chain prover (`/v1/zkquery`)
- **API key is NOT a Bearer token.** Exchange first at `POST https://proxy.api.makeinfinite.dev/auth/apikey` with header `apikey: <key>`. Returned `accessToken` (25-min JWT) goes into `Authorization: Bearer <token>`.
- **Endpoint root is `https://api.makeinfinite.dev`** — the SDK appends `/v1/zkquery` (submit), `/v1/zkquery/{id}/status` (poll), `/v1/zkquery/{id}/results` (fetch). Never use `/v2/sql` — that path returns generic Go 404.
- **`sourceNetwork` is the literal uppercase string `"MAINNET"`.** Only accepted enum value, even for user-published Community-tier tables. `"mainnet"`, `"USER"`, `"MANAGED"`, etc. all return 400.
- **`commitmentScheme: "HYPER_KZG"`** matches our `tables.createTables` config (`{ Empty: { hyperKzg: true } }`).
- **`blockHash` must come from `attestation_v1_bestRecentAttestations`** on the SXT chain RPC — binds the proof to recent attested chain state.

### On-chain (Base + Ethereum)
- **QueryRouter:** `0x220a7036a815a1Bd4A7998fb2BCE608581fA2DbB` (same address on Base + Ethereum mainnet).
- **`version` constant:** `keccak256("latest")` = `0x5d7c83ff6d08efb2f110018d8b6814a4719a93273a3ea09ced5cfe0d5db1d001`. Hardcoded in `examples/contracts/sxt-onchain-query/src/libraries/ProofOfSQL.sol`. Don't substitute the verifier address (a prior bug we corrected).
- **Verifier addresses:** Base `0x13b7463a07Aac6Bd483E4329a7F6768Da1A65518`, Ethereum `0x55780Ba21EdFBbFEb7033a0F2FC5Cf55Cd62ACf9`.
- **SXT ERC-20:** Base `0xA2c22252cDc8b7cDdEe1B0b2E242818509fCf7b8`, Ethereum `0xE6Bfd33F52d82Ccb5b37E16D3dD81f9FFDAbB195`.
- **`query()` payment is 100 SXT** + ~$0.50 ETH gas. Refunds happen via `cancelQuery(bytes32 queryId, Payment payment)` (TWO args; the Payment struct must match the original `QueryRequested` event verbatim) — only after the 1-hour payment timeout expires.
- **Callback selector** for `OnchainQuery.queryCallback` and `StakersQuery.queryCallback` is `0xd1eefc40`.

### Code structure
- **`StakersQuery.sol` is canonical and hand-curated.** `render-onchain-query.mjs` REFUSES `--name StakersQuery` and writes to `OnchainQuery.sol` instead. Never have the renderer overwrite it. To update its baked-in plan after a republish, edit `StakersQuery.sol` manually (regenerate plan via `commitments_v1_evmProofPlan` for the matching SQL, swap the `QUERY_PLAN` hex constant + the chain-state-hash doc comment).
- **`OnchainQuery.sol` is auto-generated** from `examples/contracts/sxt-onchain-query/templates/OnchainQuery.sol.template`. Never edit `src/OnchainQuery/OnchainQuery.sol` directly — re-run the renderer.
- **`.deploy-state.json` is the deploy idempotency guard.** Delete it to force a redeploy; otherwise the script reuses the prior address.
- **Don't copy external reference contracts into `src/`** (the SXT HelloWorld.sol, etc.) — cite the upstream URL instead. The `src/` tree is the compile path.

## Failure-mode quick reference

| Symptom | First check | Likely cause |
|---|---|---|
| `/v1/zkquery` returns `422 "does not exist in source network MAINNET"` | Did the publish use a `PRIMARY KEY` clause? | PK in DDL — republish without it, under a new namespace |
| `/v1/zkquery` returns `400 "source network 'X' is not supported"` | Body's `sourceNetwork` value | Must be literal `"MAINNET"` — uppercase, case-sensitive |
| `401 SECURITY: Invalid JWT` | Did you exchange the API key first? | Send raw API key to `/auth/apikey` (header `apikey:`), use the returned `accessToken` as Bearer |
| `query()` times out at 1 hour with no callback | `check-executor-activity.mjs 48` | If executor is alive (99%+ fulfillment) but ours skipped → table not in MAINNET catalog → see PK rule above |
| Deploy script "Already deployed at 0x…" | `.deploy-state.json` exists | Delete it to force redeploy |
| `forge build` "Identifier already declared" | `dependencies/` mismatch | `forge clean && forge soldeer install` |
| Renderer error `--name StakersQuery refused` | Trying to overwrite the canonical contract | Use a different `--name` — StakersQuery is hand-curated |

## Tone and behavior rules

- **Diagnose root causes before retrying.** When a command fails, read the error before re-running. Don't loop on transient retries.
- **Gate real-money operations behind explicit confirmation.** Deploys (~$0.50 ETH) and `query()` (100 SXT) require user approval. Off-chain pre-flights (`/v1/zkquery` REST) are zero-cost — use them to validate before spending on-chain.
- **Verify off-chain before spending on-chain.** A successful `/v1/zkquery` proof is mathematically guaranteed to fulfill on-chain (same backend). A 422 means *don't spend*.
- **Match the canonical SXT examples** ([`spaceandtimefdn/sxt-chain-examples`](https://github.com/spaceandtimefdn/sxt-chain-examples)) when in doubt about publishing flow. Our `publish-dataset-cli.mjs` mirrors the Hello World tutorial — diff against it before adding novel parameters.
- **Brief responses unless asked otherwise.** State results, surface verifiable evidence (tx hashes), and stop. Don't pad with exploration prose.
