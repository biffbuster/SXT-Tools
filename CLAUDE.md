# CLAUDE.md — agent operating instructions for this repo

You are Claude Code working inside the **sxt-tools** repository: a Claude Code marketplace shipping three plugins (`dreamspace-data`, `dreamspace-query`, `dreamspace-contracts`) and seven skills that take a CSV or a verified EVM smart contract (or SXT-indexed Ethereum chain data) from a local folder to a verifiable Proof-of-SQL event on Base mainnet via Space and Time chain.

This file captures the load-bearing rules for working *inside* this codebase. The human-facing documentation is in [`README.md`](./README.md) (overview/quickstart) and [`HOW_IT_WORKS.md`](./docs/HOW_IT_WORKS.md) (architecture). Read those before responding to onboarding questions; read this file before *modifying* anything.

---

## Architecture in one paragraph

A dataset reaches the proven surface via one of two input paths: (A) a CSV published to SXT chain via two Substrate extrinsics (`tables.createNamespace` + `tables.createTables` then `indexing.submitData`), or (B) a verified EVM smart contract registered via SXT Smart Contract Indexing (SCI) so SXT auto-generates per-event tables under the user's namespace. Either way the chain indexer promotes the table into the dreamspace.xyz Studio MAINNET catalog. A user-deployed Solidity contract on Base calls `IQueryRouter.requestQuery` with a hex-encoded proof plan generated by the SXT chain RPC `commitments_v1_evmProofPlan`. The SXT executor reads the plan, runs the SQL against the indexed table, generates a HyperKZG proof, validates it through Base's onchain Verifier in ~150K gas, and calls back into the user's contract — emitting an event that's a trustless cryptographic receipt. The seven skills wrap each step.

## Load-bearing rules (NEVER break these)

### Publishing
- **NEVER emit `PRIMARY KEY` in CREATE TABLE.** SXT chain accepts the DDL and rows ingest, but the dreamspace MAINNET indexer silently skips promotion → off-chain `/v1/zkquery` returns `422 "does not exist in source network MAINNET"` → on-chain executor silently drops `query()` calls → 100 SXT locks until 1-hour timeout. Verified failure mode that cost us 200 SXT before discovering it. `publish-dataset-cli.mjs:117` is the load-bearing line — keep it `NOT NULL`-only.
- **`publish-dataset-cli.mjs` auto-writes the inferred schema** to `<csv-base>.inferred-schema.json` alongside the CSV after a successful publish. Downstream scripts (`save-proof-plans.mjs` via `SXT_SCHEMA_PATH`, `render-onchain-query.mjs` via `--schema`) read this artifact. Hand-curated `*.schema.json` files still take precedence when present. **Don't remove the schema writeout** — it's the bridge that makes the pipeline schema-agnostic for arbitrary CSVs.
- **`save-proof-plans.mjs` is column-aware.** It reads the schema, picks the first VARCHAR column as the lookup target by default (or `SXT_LOOKUP_COLUMN` if set), and formats the SQL literal correctly per column type (`'string'` for VARCHAR, raw numeric for BIGINT, etc.). When generalizing to a new dataset shape, you generally need to set only `SXT_TABLE`, `SXT_POINT_LOOKUP`, and (if multi-VARCHAR) `SXT_LOOKUP_COLUMN`.
- **Default `SXT_RPC` is `wss://rpc.mainnet.sxt.network`.** Testnet is opt-in via env override. The publish *flow* mirrors the canonical [`spaceandtimefdn/sxt-chain-examples`](https://github.com/spaceandtimefdn/sxt-chain-examples/tree/main/tutorials/create_hello_world_table) tutorial (batchAll, NOT NULL, hyperKzg, EthEcdsaSigner) — but note the tutorial itself targets `wss://rpc.testnet.sxt.network`; our mainnet default is a deliberate divergence, not a mirror.
- **Namespace must end with the publishing wallet's uppercase hex address.** `publish-dataset-cli.mjs` auto-suffixes — don't bypass.
- **Apache Arrow vectors must carry explicit types** (`vectorFromArray(values, new Utf8())`). Inferred typing via `tableFromJSON` is rejected with `indexing.ArrowExpectedRecordBatchMessage`.

### Off-chain prover (`/v1/zkquery`)
- **API key is NOT a Bearer token.** Exchange first at `POST https://proxy.api.makeinfinite.dev/auth/apikey` with header `apikey: <key>`. Returned `accessToken` (25-min JWT) goes into `Authorization: Bearer <token>`.
- **Endpoint root is `https://api.makeinfinite.dev`** — the SDK appends `/v1/zkquery` (submit), `/v1/zkquery/{id}/status` (poll), `/v1/zkquery/{id}/results` (fetch). Never use `/v2/sql` — that path returns generic Go 404.
- **`sourceNetwork` is `MAINNET`** (the MakeInfinite OpenAPI enum is `MAINNET` | `TESTNET`; the prover is case-insensitive, verified 2026-11-16). The SDK and `lib/prover.ts` send lowercase `"mainnet"`, which is fine. `"USER"`, `"MANAGED"`, and other values return 400 "Invalid source network". Only mainnet holds the proven catalog, even for user-published Community-tier tables.
- **`commitmentScheme: "HYPER_KZG"`** matches our `tables.createTables` config (`{ Empty: { hyperKzg: true } }`).
- **`blockHash` must come from `attestation_v1_bestRecentAttestations`** on the SXT chain RPC — binds the proof to recent attested chain state.

### On-chain (Base + Ethereum)
- **QueryRouter:** `0x220a7036a815a1Bd4A7998fb2BCE608581fA2DbB` (same address on Base + Ethereum mainnet).
- **`version` constant:** `keccak256("latest")` = `0x5d7c83ff6d08efb2f110018d8b6814a4719a93273a3ea09ced5cfe0d5db1d001`. Hardcoded in `examples/contracts/sxt-onchain-query/src/libraries/ProofOfSQL.sol`. Don't substitute the verifier address (a prior bug we corrected).
- **Verifier addresses:** Base `0x13b7463a07Aac6Bd483E4329a7F6768Da1A65518`, Ethereum `0x55780Ba21EdFBbFEb7033a0F2FC5Cf55Cd62ACf9`.
- **SXT ERC-20:** Base `0xA2c22252cDc8b7cDdEe1B0b2E242818509fCf7b8`, Ethereum `0xE6Bfd33F52d82Ccb5b37E16D3dD81f9FFDAbB195`.
- **`query()` payment is 100 SXT** + ~$0.50 ETH gas. Refunds happen via `cancelQuery(bytes32 queryId, Payment payment)` (TWO args; the Payment struct must match the original `QueryRequested` event verbatim) — only after the 1-hour payment timeout expires.
- **Callback selector** for `OnchainQuery.queryCallback` and `StakersQuery.queryCallback` is `0xd1eefc40`.

### MCP server (`packages/mcp/sxt-mcp/`)
- **The MCP server is built in partnership with Space and Time** (confirmed 2026-10-12). Use that one-line notice wherever the project describes its relationship to SXT. It wraps the canonical SXT toolchain, mirrors the existing `examples/scripts/*.mjs` request shapes, never invents new protocol logic, and ships behind a phased rollout + mainnet double-gate. The package's `SAFETY.md` is the contract — the phased rollout (v0.0.1 → v0.5.0) and the mainnet double-gate (`mainnet: true` arg + `SXT_MCP_ALLOW_MAINNET=I-UNDERSTAND` env) are **load-bearing rules**, not suggestions. PRs that skip phases or weaken the gate get bounced.
- **Current phase: v0.4.0.** Eight tools live, mainnet enabled behind the double-gate. (0) `sxt.list_tables` + `sxt.describe_table` — free discovery. `describe_table` is keyless: it compiles `SELECT * FROM <table>` via `commitments_v1_evmProofPlan` against the mainnet catalog; error 254018 means not provable, and the plan head encodes every column's name and type (`decodePlanColumns` in `tools/catalog.ts`). `list_tables` pages through every public community table via the MakeInfinite discovery API (`/v2/discover/schema` then `/v2/discover/table` per schema, Bearer JWT, no credit; `src/lib/discovery.ts`), cached process-wide for 15 minutes with in-flight dedupe and at most 12 uncached schema fetches per call; with no key it falls back to the curated `KNOWN_TABLES`. `ETHEREUM.TRANSACTIONS` is in `UNSTABLE_TABLES`: hidden from the list and refused by `run_proven_query`, because proofs against it fail and twice stalled the prover for every user (2026-11-10, 2026-11-16). The CLI mirror is `sxt tables` (`examples/scripts/tables.mjs`). On the live catalog, Ethereum hashes and addresses are VARBINARY (hex literal `X'…'` or bare `0x…`), and DECIMAL/TIMESTAMP columns cannot be compared in WHERE (verified 2026-11-10). (1) `sxt.run_proven_query` — off-chain `/v1/zkquery` against any public table (cross-owner proof verified on IRIS 2026-11-17). Before submission: the regex surface check, a free chain-RPC planner preflight (unsupported SQL returns `SQL_REJECTED` with the planner's reason), and a 50 MB guard that refuses SQL with neither WHERE nor LIMIT. Aggregates prove only with GROUP BY on one non-VARCHAR column (verified 2026-11-17); ungrouped aggregates plan but fail at execution and are refused (`SXT_MCP_ALLOW_AGGREGATES=1` lifts it). Verified results carry `rows` (DECIMAL decoded from big-endian u64 limbs to exact strings, VARBINARY as hex) next to the raw `result`. A prover execution failure maps to non-retryable `QUERY_FAILED`. `src/lib/prover.ts` sends the same requests as the SDK's `queryAndVerify` (SDK pinned exactly at 0.54.0; re-diff before bumping) but retries the free calls and **never retries the submit**, the only call that spends a credit. A proof still running after `waitSeconds` returns a pending `queryId`; `sxt.get_proof_result` resumes it for free. (2) `sxt.audit_contract` — pure local execution: `forge build` + optional `slither`, computes SHA-256 of every `.sol` source. (3) `sxt.publish_dataset` — testnet-default Substrate publish via `@polkadot/api` + Apache Arrow IPC + the `EthEcdsaSigner` from `src/lib/eth-ecdsa-signer.ts` (TypeScript port of `examples/scripts/ethecdsa_signer.mjs`); enforces NOT NULL on all columns, no PRIMARY KEY, auto-suffixes namespace with the wallet's hex address; idempotent (catches `*AlreadyExists` errors and proceeds to insert). (4) `sxt.deploy_contract` — testnet-default (Sepolia) deploy via ethers `ContractFactory` from a forge artifact; idempotent via `.deploy-state.json`; refuses `forceRedeploy` on mainnet. (5) `sxt.generate_proof_plan` — compiles SQL to an EVM proof plan via `commitments_v1_evmProofPlan`; supports parameterized plans (`$1`, `$2`); zero cost and needs no credentials; this is the bridge from a published table to an on-chain proof. Every tool that writes to a chain or spends from a wallet routes through `selectNetwork()` for the mainnet gate; prover-catalog reads (run_proven_query, get_proof_result, list_tables, describe_table) are exempt because the prover has only the mainnet catalog and they write nothing (SAFETY.md, Mainnet gate).
- **Hosted (public) mode never spends the operator's key.** Setting `SXT_MCP_PUBLIC_URL` makes `sxt-mcp-http` a multi-user connector: OAuth 2.1 via the SDK's `mcpAuthRouter`, the user enters their own SXT key on a consent page (checked with the free `/auth/apikey` exchange), and every token is AES-GCM sealed over that key under `SXT_MCP_TOKEN_SECRET`, so there is no database. `buildServer({ credentials: "request" })` forbids the env-key fallback; `surface: "hosted"` forbids filesystem writes and returns only sanitized error codes. Only tools in `HTTP_READ_ONLY_TOOLS` (list_tables, describe_table, run_proven_query, get_proof_result, generate_proof_plan) are reachable over HTTP. Keep all three properties when adding tools. Rules and env vars: `packages/mcp/sxt-mcp/SAFETY.md` → "Public mode".
- **Production hosting is Cloudflare Workers** (`packages/mcp/sxt-mcp/wrangler.jsonc`, `src/worker/index.ts`), running the same `http-app.ts` as the Node/Docker fallback. HTTP entrypoints build from `core.ts` + `tools/catalog-read.ts` and must never import `server.ts` or a write tool. The SDK verifier's WASM is extracted at build time by `scripts/build-worker-verifier.mjs`, pinned to SDK 0.54.0 by version and sha256; an SDK bump fails that build until the transform and `lib/prover.ts` are re-reviewed.
- **The MCP publish data path requires value coercion.** `csv-parse` yields strings and Arrow's typed builders do not parse them: a raw `["true","false"]` into `new Bool()` silently yields `[false,false]`, and a `TimestampMillisecond` builder throws on ISO input. `coerceValues()` in `publish-dataset.ts` sits between them, and `scripts/day1-smoke.mjs` asserts the round-trip. Never hand raw CSV strings to `vectorFromArray`.
- **`batchAll` is atomic, so the second publish from a wallet needs a fallback.** When `createNamespace` fails with `NamespaceAlreadyExists` the whole batch rolls back and `createTables` never landed; going straight to `submitData` fails with `indexing.UnauthorizedSubmitter`. Both `publish-dataset-cli.mjs` and the MCP handler re-submit `createTables` alone against the existing namespace.
- **Docs served as MCP resources must be bundled.** `scripts/bundle-docs.mjs` runs at `prebuild` and copies `proof-of-sql-foundations/SKILL.md` into the package's `docs/`, which ships in the tarball. Without it an npm-installed server resolves nothing and every installed user silently gets the fallback stub. When adding a resource-backed doc, add it to that script's `DOCS` list.
- **Default networks invert from the CLI scripts.** Existing scripts default to mainnet because they're operated by humans who know what they're doing. The MCP server defaults to testnet because it's invoked by agents with no informed consent. The `lib/network.ts` `selectNetwork()` function is the single chokepoint — every tool that writes or spends must call it.
- **Env var names match the existing scripts** (`PRIVATE_KEY`, `SXT_RPC`, `SXT_API_KEY` / `MAKEINFINITE_API_KEY`, `ETH_RPC`) so users don't relearn anything when moving between CLI and MCP.
- **The server started with only `@modelcontextprotocol/sdk` + `zod`** in v0.0.1 (zod 4 since 2026-11-16; tool input schemas come from the native `z.toJSONSchema`, so `zod-to-json-schema` is no longer a direct dependency). Heavy SXT deps (`@polkadot/api`, `apache-arrow`, `ethers`, `sxt-proof-of-sql-sdk`) are added phase-by-phase as their handlers come online — keeps the install fast and prevents accidental import surface.

## Failure-mode quick reference

| Symptom | First check | Likely cause |
|---|---|---|
| `/v1/zkquery` returns `422 "does not exist in source network MAINNET"` | Did the publish use a `PRIMARY KEY` clause? | PK in DDL — republish without it, under a new namespace |
| `/v1/zkquery` returns `400 "source network 'X' is not supported"` | Body's `sourceNetwork` value | Must be `MAINNET` (any case) |
| `401 SECURITY: Invalid JWT` | Did you exchange the API key first? | Send raw API key to `/auth/apikey` (header `apikey:`), use the returned `accessToken` as Bearer |
| `query()` times out at 1 hour with no callback | `check-executor-activity.mjs 48` | If executor is alive (99%+ fulfillment) but ours skipped → table not in MAINNET catalog → see PK rule above |
| Deploy script "Already deployed at 0x…" | `.deploy-state.json` exists | Delete it to force redeploy |
| `forge build` "Identifier already declared" | `dependencies/` mismatch | `forge clean && forge soldeer install` |
| Renderer error `--name StakersQuery refused` | Trying to overwrite the canonical contract | Use a different `--name` — StakersQuery is hand-curated |

## Tone and behavior rules

- **Diagnose root causes before retrying.** When a command fails, read the error before re-running. Don't loop on transient retries.
- **Gate real-money operations behind explicit confirmation.** Deploys (~$0.50 ETH) and `query()` (100 SXT) require user approval. Off-chain pre-flights (`/v1/zkquery` REST) are zero-cost — use them to validate before spending on-chain.
- **Verify off-chain before spending on-chain.** A successful `/v1/zkquery` proof is mathematically guaranteed to fulfill on-chain (same backend). A 422 means *don't spend*.
- **Match the canonical SXT examples** ([`spaceandtimefdn/sxt-chain-examples`](https://github.com/spaceandtimefdn/sxt-chain-examples)) when in doubt about publishing flow. Our `publish-dataset-cli.mjs` mirrors the Hello World tutorial — diff against it before adding novel parameters.
- **Brief responses unless asked otherwise.** State results, surface verifiable evidence (tx hashes), and stop. Don't pad with exploration prose.
